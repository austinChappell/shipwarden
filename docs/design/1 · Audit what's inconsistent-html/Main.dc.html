ShipWarden · design consistency pass

15 places the app disagrees with itself

Pulled from the 20 screenshots. The look (dark navy, blue accent, system type, 10px cards) is already coherent; what drifts is structure: headers, button weights, chips, counts, and states. Each finding ends in one rule. Boards 2–4 show the rules applied.

High impact: 1–6 Medium: 7–12 Polish: 13–15
01

Page headers come in four shapes

Seen

  • Icon + title + meta: Dashboard, Notes, Automations, Plans, repo graph
  • Title, no icon: Agents
  • No title at all, controls start at the left edge: Tasks, Review, Pipelines, worktree
  • Breadcrumb + close: Settings

Rule

Every page header: icon + title + one meta line on the left, scope controls next to it, then a spacer, then filter, icon actions, and at most one primary button on the right. Settings keeps its breadcrumb because it is a modal layer. (Board 3)

02

Filter fields move and change their wording

Seen

  • Right side on Dashboard, first item on Review, beside the title on Notes, after six dropdowns on Tasks
  • “Filter by title, ticket, repo…”, “Search tasks”, “Search names, folders, a…” (truncated), “Filter repositories”, “Find files by name”
  • The / shortcut hint shows on 2 of 6

Rule

One filter field, 240px, always in the right group, placeholder “Filter <things>”, always with the / hint. Reserve “Search” for a future global search.

03

Button weight has no rule

  • Filled: New note, New plan, New, Start review queue
  • Blue outline: Merge, Merge both, Start an agent, Start Claude Code, Pair a phone, Add rule
  • Neutral: Open, Folder, Import, Test, Choose…, Clear, Send a test

Rule

Primary (filled) = the page's main create/start, one per view, including the empty-state button. Secondary (neutral) = everything else. Soft accent only for the one recommended row action (Merge). Drop the blue outline style.

04

Chips come in seven shapes

CI failing Conflict no ticket 2 unresolved spike api #3199 :5173 +2

Rule

One chip: 20px tall, radius 6, 12px/500, soft tone fill, no border. Tones: neutral, info, success, warning, danger, review. Monospace only for identifiers (repo #, port, branch). Outline is reserved for git refs in the graph. “no ticket” becomes a warning chip; “2 unresolved” becomes a neutral chip with a comment icon.

05

Counts are written six ways

Your pull requests · 24 2 14 1 #note 2

Rule

One count badge (18px pill, 11px/600). Neutral after any heading or filter. Accent only when the number means “needs you” (sidebar Dashboard and Review, Review's To review column). No “· N” text counts.

06

Empty and waiting states have no pattern

  • Centered icon, title, text, outline button: Agents, worktree
  • Plain grey text in the top-left corner: “Select a note.”, “Select a run to see its jobs and logs.”
  • “Loading runs...” as text with three dots
  • Dashed box “No tasks” in an empty Kanban column

Rule

Pane empty state = centered icon, title, one line, primary button, optional shortcut hint. Selection placeholder = same layout without the button. Loading = skeleton rows in the shape of the result. Empty column keeps the dashed box. (Board 4)

07

Sort and view toggles use two controls

By author Oldest first In projects All

Rule

The track segmented control everywhere (Review, repo graph, Settings, Automations already use it). The Dashboard's By author / Oldest first / By repo pills switch to it.

08

Section headings mix three styles

  • Caps eyebrows: YOUR PULL REQUESTS, WAITING ON YOU, WORKFLOWS, REPOSITORIES, NOTHING WAITING
  • Bold title case: Run automations, History, Paired phones, New pull request comments
  • A 22px headline in the body: Review's “1 pull request waiting on you”

Rule

Caps eyebrow = a group inside a list or column. 15/600 title + 13px description = a card or form section. No headline in the body: Review's summary moves into the header meta line.

09

Ages and times use five formats and two color rules

  • “7h”, “7 h ago” (repo graph has a space), “16h ago”, “Last activity 6h ago”, “oldest waiting 1 day”
  • Review's Oldest column is red for every value (8w–18w); Dashboard ages stay grey until 4w

Rule

Columns: “7h · 2d · 4w”. Prose: “7h ago”. Age tone by threshold everywhere: muted under 7 days, warning 7–29 days, danger 30 days and up (matches the Stale 30d+ tile).

10

Refresh lives in five places

  • Top-right on Dashboard and Pipelines, beside a gear on Tasks, left of the primary button on Review, after the segmented control on the repo graph, plus the footer

Rule

Icon actions sit together just left of the primary button; refresh is always the last icon. Pages that refresh show “Updated 1m ago” in the meta line, like the Dashboard does.

11

Content width and gutter change per page

  • Dashboard and Review: full width, ~28px gutter
  • Automations and Plans: ~1100px column, ~44px gutter
  • Settings: ~960px column, indented ~80px past its nav

Rule

One 32px gutter. Data pages (Dashboard, Review, Tasks, Pipelines) go full width. Form pages (Settings, Automations, Plans) use an 880px column, left-aligned at the gutter.

12

Disabled controls look two ways

Rule

Disabled = the button's normal style at 40% opacity. “Add rule” becomes a secondary button.

13

Status colors are reused for other meanings

  • Purple = Changes requested, but also “unresolved” text and the spike / integrations labels
  • Red = Blocked and CI failing, but also every Review age and the Remove button
  • Footer: “Claude” in orange, “Codex” in white

Rule

Reserve the five Dashboard tile hues for PR state. Task labels get a separate muted label palette. Destructive buttons use red text only. Both provider names in the footer use the label color; the bar carries the provider color.

14

Text fields size at random

  • Worktrees › Branch names: a ~400px field truncates “story/{taskKey}/{taskShortDescr…”
  • Mixed full-width and fixed fields on the same Settings page

Rule

Text fields fill the row. Only short typed values (port, percent, number) get a fixed 120px field.

15

Copy nits

  • “No agents run now” → “No agents running”
  • Plans: “1 pull requests” → “1 pull request”
  • “...” → “…” (Loading runs, Choose, Add a provider, Filter by…)
  • Agents header repeats “Plan usage: Claude 39% · Codex 0%” from the footer; remove it
  • Two plans both titled “New plan”: name new plans from their first step

Rule

One pluralize helper, the real ellipsis character, and no number shown twice on one screen.
